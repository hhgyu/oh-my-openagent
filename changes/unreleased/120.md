### Fixed

- The private sign-in file no longer refuses every home on a host that cannot report a POSIX owner (Windows). There, owner and mode bits are not judged, while symlinks and non-directories are still refused. On Linux the full owner and mode check is unchanged.

## 2026-11-26 - Judge credential ownership only where the host can answer it (#120)

The credential parent check added for the Linux sign-in file compared directory owners with a uid of -1 on hosts without `process.getuid`, so any store using the Linux family there refused its home as a foreign owner. The state file store now takes its owner from an injectable `getuid` (default `process.getuid`), judges owner and mode only for a real uid, and treats Windows' refusal to flush a directory handle as a filesystem that cannot sync directories.
