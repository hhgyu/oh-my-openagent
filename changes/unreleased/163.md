### Fixed

- On Windows, stopping a memory git (abort or timeout) no longer runs `taskkill` against a git that has already exited. taskkill looks its target up by process id a few hundred milliseconds after it starts. A git that finished meanwhile had its process id freed, so taskkill either failed with "not found" (and an aborted git that had in fact finished was reported as a failed stop) or could end an unrelated process that had reused the id, along with its whole tree. An exited git now settles without taskkill. For a running git, taskkill runs while the git's process id is still held, so it can only ever reach that git's own tree.
