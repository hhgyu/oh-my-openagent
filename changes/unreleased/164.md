### Fixed

- On Windows, the side panel's diff of an untracked file no longer comes back as "no textual change" when a `\dev\null` directory exists on the drive the repository is on. Git for Windows resolves the `/dev/null` argument against the current drive before treating it as the null device, so the panel now passes `NUL` there.

- On Windows, saving a task (`task_create`, `task_update`) no longer fails with `internal_error` when another handle still holds the task file for a moment. A replacing rename that Windows refuses with a sharing violation (EPERM, EBUSY or EACCES) is retried a bounded 8 times, 5 ms apart, the same as the Senpi task record store; other platforms and other errors fail as before.

### Changed

- Memory git diagnostics (`OMO_GIT_TIMEOUT_DIAGNOSTICS_DIR`, off unless set) now also record a git that is still running at half of a budget of 10 s or more: a `git-stall-<pid>-<ts>.json` with the process table and its volume snapshot evidence, taken while the git is still stalled. The git keeps its full budget and its caller never waits for the record; no timeout or retry changes. A record that has started runs its process snapshot (at most 15 s) and volume collector (at most 10 s) to completion, which can keep the process open that long. Previously only a git that ran out its whole budget was recorded, which a caller with a shorter deadline of its own never saw.
