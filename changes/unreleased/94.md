### Fixed

- On OpenCode 2, when two server processes serve one project (a `serve --service` restart replaces the previous service), only one of them now revives a task child an OpenCode restart left behind. The other no longer posts a `not revived: Owned unadmitted cleanup incomplete` notice, no longer refuses that child's tool calls with `Owned child is not executable`, and takes the child over once the first process lets it go. A parent call that reaches a child the other process still holds says so instead of `Operation task has no original owned membership`.
- `task_cancel` ends a task child that a restart left parked or stranded, or whose revival failed, instead of failing with `no original owned membership`; it no longer revives the child it is cancelling first, and a cancelled child does not revive at the next start.
- A plugin location reload while a revived task child's turn runs hands the child to the reloaded plugin: the reload no longer waits forever for that turn, and task calls are no longer refused for 30 s with `previous plugin generation ... still parking`.

## 2026-11-18 - Single-owner task revival, cancel of left-behind children (#94)
