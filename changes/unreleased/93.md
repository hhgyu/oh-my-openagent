### Fixed

- An OpenCode 2 task child that a server restart cut off while a tool was running now finishes its revived turn with one completion notice, and the parent's next `task_send` continues it. Before, the host's settlement of the interrupted tool call made the revived turn's observation uncertain (`unmatched-step`): the task stayed `running`, no completion arrived and `task_send` was refused.
- When the restarted OpenCode host itself resumes such a child and the revival adopts the answer it finished, the parent's next `task_send` continues the child instead of failing with `could not be revived: Owned prior turn is not positively settled`.

## 2026-11-18 - Restart-revived task children stay continuable (#93)

`host/owned-child-outcome.ts`: a later-turn observer skips a `session.tool.failed` (`aborted`) for a step it never saw start, when it arrives in a run that has not yet started a step or delivered input. OpenCode 2.3.0 emits exactly that for the tool call a restart interrupted, as it starts the run that delivers the restart continuation. `orchestration/native-task/owned-handle.ts`: a recovered turn settled by adopting the host's finished answer records its run epoch, and the follow-up barrier accepts that receipt for a `completed` record of the same run and residency claim.
