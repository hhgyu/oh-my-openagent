## 2026-11-26 - Record Volume Shadow Copy evidence with a Windows git timeout (#122)

A Windows CI `git add` that waited past its 30 s timeout was attributed to a Volume Shadow Copy snapshot only by process start times. The opt-in git timeout record is still written before the kill, exactly as before, and is never modified afterwards. Once the timed-out git has been signalled, `<record>.vss.json` is published next to it. It holds VSS, VSSVC, volsnap and VolumeSnapshot-Driver events from the Application and System logs for the last 10 minutes, each with its UTC time, plus the `VSSVC.exe` process with its creation time. Each provider is queried on its own, so one provider's error is recorded without hiding the others. A collector that exits nonzero, writes to stderr or throws publishes `{ error, exitCode, stderr, partial }` instead. Every publish writes a temp file and renames it into place, so the sibling file is either absent or complete. At the 10 s deadline a timeout marker is published, and a result that arrives later is discarded. Git's timeout and kill timing are unchanged. The CI evidence artifact already uploads the whole diagnostics directory, so the sibling file is included.
