## 2026-11-26 - Record Volume Shadow Copy evidence with a Windows git timeout (#122)

A Windows CI `git add` that waited past its 30 s timeout was attributed to a Volume Shadow Copy snapshot only by process start times. The opt-in git timeout record is still written before the kill, exactly as before. Once the timed-out git has been signalled, a `volumeShadowCopy` field is added on Windows. It holds VSS, VSSVC, volsnap and VolumeSnapshot-Driver events from the Application and System logs for the last 10 minutes, each with its UTC time, plus the `VSSVC.exe` process with its creation time. Each provider is queried on its own, so one provider's error is recorded without hiding the others. One 10 s deadline covers the collection and the record update. If the collector fails or misses the deadline, the record keeps its process snapshot and gains a `volumeShadowCopyError` marker. Git's timeout and kill timing are unchanged.
