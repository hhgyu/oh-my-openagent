### Fixed

- OpenCode 2: an in-process location reload or evict while a Native task child or `workflow` node was still mid-turn no longer strands it. Before, the previous plugin generation never parked the child, its task row stayed `running` under the live server, and after the reload `workflow wait` failed the node with `resume_task_orphaned` while `task_send` to the child was refused. The previous generation now parks its children as soon as OpenCode shuts the location down. The next generation's first call waits for that park, then restores the child and continues its cut-off turn exactly once, as after a server restart. A `task_send` to such a child revives it the same way before its message is delivered. If the previous generation has not finished parking within 30 s, the call fails with a clear error instead of waiting.
- OpenCode 2: after a reload, `task_output` no longer fails with `Operation task has no original owned membership` when another child of the same lead is still parked. This also covers a child the lead had just revived with `task_send`.

## 2026-11-12 - OpenCode 2 in-process reload parks mid-turn children (#28)

Root cause of D-A: OpenCode 2.2.6 `LocationServiceMap.invalidate` (`packages/core/src/location-services.ts`) detaches the location and runs `LocationLifecycle.shutdown`, which only closes permissions, forms and RPC and publishes `location.shutdown`. The location's scope, and with it the plugin registry's `close` finalizer (`plugin/supervisor.ts`), closes only when the last borrower lets go, and a running step keeps borrowing until its model request finishes (`session/runner/llm.ts`). A child held mid-turn therefore kept the retired generation open and its row `resident` under the live pid. Fix, part 1: the Native task component watches `location.shutdown` for its own location (`native-task/location-shutdown.ts`) and runs its memoized close then. The close runs as a retirement in a process-wide handover keyed by project directory (`native-task/generation-handover.ts`), and `service.parent` makes every call of a newer generation wait until no older generation of the directory is closing, bounded by `PREDECESSOR_WAIT_MS` (30 s, OpenCode's own held-location warning window): past it the call fails with `PredecessorParkTimeout` and a log line, and never reads rows the predecessor may still drive. Fix, part 2 (real-host QA showed part 1 alone hung): the park interrupts the held turn, and that interrupted drain is the location's last borrower, so OpenCode closes the location scope, and runs this plugin's close, inside the drain fiber's own teardown before the execution settles (`session/run-coordinator.ts` `interrupt`/`awaitIdle`). The park's cleanup idle barriers (`host/session-backend.ts` `waitForControlIdle`, the parking `wait` in `host/child-parking-custody.ts`, and the closing `cleanup` wait) awaited `session.wait` on that same drain, a cycle. The component now aborts a `locationReleased` signal when the host itself closes it, and those barriers treat that release as the quiescence they wait for (every step that borrowed the location has ended). A `task_send` to a child parked mid-turn (`running`, `suspended` receipt for the exact row) now revives it through the restart path, so the cut-off turn continues once as a new observed turn and the message steers it (`native-task/runtime.ts` `storedSendRefusal`). Root cause of D-B: the operation's `output.list` (`native-task/operation-ports.ts`) captured every row of the parent, and `captureOperationTask` refuses a row the previous generation parked, so one parked sibling failed every `task_output`. The listing now carries only rows the call can capture (`access.owned`). Parity row P-27 updated. Real-host QA on OpenCode 2.2.6: evict and reload with the node, the child or both held mid-turn.
