### Fixed

- One invalid agent key no longer resets the whole `omo.json` view. A legacy `maxTokens`, `providerOptions`, `textVerbosity` or `thinking` on an agent is dropped on its own with a diagnostic naming it (`agents.plan.maxTokens`), and every other agent, category and section keeps applying. Before, the pruner looped on a key the agent preprocess had synthesized and the loader fell back to the all-default config.
- The OpenCode installer writes agent and category fallbacks as a `models` chain (primary first) instead of the deprecated `fallback_models`, the same rewrite the reasoning-unification migration applies, so a fresh install no longer leaves keys the canonical agent schema rejects.
- The OpenCode 2 Kibitzer picks its model from `memory.recall.category` like OmO Native: the category chain filtered to consented, catalog-available providers, never a model outside the category. When nothing resolves, the wake is skipped with one warning instead of running on the host default model.
