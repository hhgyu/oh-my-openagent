### Fixed

- A process task child whose engine takes longer than 10 s to start no longer fails as `chain_not_held: timeout` before it ever answers. The wait for the engine's first answer is now bounded by the CPU progress of the child's whole process tree (a 10 s stall window and a 120 s CPU cap, with a 10 min outer bound when the CPU cannot be read); the 10 s deadline covers only `set_retry_fallback`. This is what made the Windows `member injection residency` test fail intermittently. Ported from upstream ([#13165](https://github.com/code-yeongyu/oh-my-openagent/issues/13165), [#14808](https://github.com/code-yeongyu/oh-my-openagent/pull/14808), [#15098](https://github.com/code-yeongyu/oh-my-openagent/issues/15098)).
- On Linux, a task child's CPU time is read with the system's own clock-tick rate (`sysconf(_SC_CLK_TCK)`) instead of an assumed 100 ticks per second, so the startup stall window and CPU cap measure real CPU seconds on a kernel built with a different rate. 100 remains the fallback when the rate cannot be read. ([#14824](https://github.com/code-yeongyu/oh-my-openagent/pull/14824), fixes [#14821](https://github.com/code-yeongyu/oh-my-openagent/issues/14821))
- A task child started through a launcher that runs the engine as its own child process (an npm shim or a wrapper script) no longer fails its start as a stall while the engine boots. The startup bound now follows the CPU of the launcher's whole process tree on Linux, macOS and Windows. ([#14827](https://github.com/code-yeongyu/oh-my-openagent/pull/14827), fixes [#14820](https://github.com/code-yeongyu/oh-my-openagent/issues/14820))
