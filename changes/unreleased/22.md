### Added

- OpenCode 2 `workflow` runs now survive a plugin reload or restart. When the plugin closes, every live run is paused the way the Native runtime pauses on shutdown, and its children are parked, not cancelled. The next `workflow` call that names the run (`wait`, `resume`, or a `start` that reuses its key) restores the parked children under that call, re-attaches them and continues the run inside that call. Nothing is resumed without a call.
- OpenCode 2 `workflow action=resume` resumes a run a plugin reload paused: it recovers the run and starts what can start now, then returns like a detached wait. A run the user stopped still refuses `resume`.
- A run wake that was recorded but not delivered before a reload is delivered once after the reload, with the same message id, by the next plugin generation.

### Fixed

- An OpenCode 2 `workflow` node whose start was cut off when its call ended no longer blocks the run with "needs workflow recovery". The next `wait` resolves it with the Native recovery rules: a node that never started is started once, and a node whose task is gone is failed with an explicit reason.
- OpenCode 2 `workflow` `wait`, `resume` and `cancel` of a run a reload, a process stop or a hard kill left behind no longer fail with "Operation task has no original owned membership". The call now decides which parked children to restore without reading them through its task port, restores them first, and only then attaches, folds or cancels them.
- A `workflow` call from a second OpenCode process on the same project no longer erases the first process's run lease holder when it ends; the holder it displaced is written back.
- A `workflow` node whose child was still working when OpenCode stopped, was killed or reloaded no longer fails with "Child observation uncertain: observation-invalidated" after recovery. The restored child continues its interrupted turn with Native's host-restart continuation, and the node completes from that turn.
- A `workflow` call from a second OpenCode process no longer pauses and fails a run the first process is still driving. It is refused with `run_still_active`, and a run another process already settled is never overwritten by a scheduler that did not settle it.

## 2026-11-12 - OpenCode 2 workflow recovery (#22)

S6f of the OpenCode 2 DAG port. Every `workflow` drive now claims the S6c generation lease (`native-dag/lease.ts` `claimDagRunLease`: `leaseHolderPid` = this generation's holder, dropped after the call like Native `releaseLease`), so a run another live generation holds is refused with `run_still_active`. On component close, after the task service has ended every call and parked every child, `NativeDagRuntime.pauseForShutdown` waits for the drives to retire and runs Native `pauseRunsForShutdown` (`dag.run.paused` with `session_shutdown`, the lease moved to `previousLeaseHolderPid`, no child cancelled). A drive with no control verb first restores, through Native task's `restoreAfterReload` under the call's fresh approval, every admitted node child a reload parked; a run that is paused, or has a node with no recorded or owned task, or a child no host backs, then goes through Native recovery inside the call (`native-dag/recovery.ts` `recoverDagRun`): a running run is first paused like a shutdown, and Native `installPausedRuns`, over a store view that shows only this run, claims it under the generation lease, reconciles every node, journals `dag.run.resumed` and installs a scheduler whose every start goes through the call's held port. The DAG call port now carries `getResidentHandle` (new `recovery.residentHandle` on the Native task operation, original parent only) for Native recovery's orphan check, and `restoreAfterReload`. `workflow action=resume` on a reload-paused run recovers it detached. At startup the component discovers every root with a DAG store (`native-dag/discovery.ts`, run records whose parent hashes to that state directory, never when the project is $HOME) and arms each live run on the new wake owner, so an un-ACKed wake is re-posted with its same id and text after every re-check. `cancel_node` keeps its refusal: Native exposes no model pause or stop action. The store lock files keep their pid holder (held for one synchronous operation only), and `amend-safety.ts` keeps its pid probe, which a generation holder can never pass. Live-host QA defect D-1 fixed: recovery (`native-dag/recovery.ts` `restoreRunChildren`) decides whether a node's child needs restoring from the owned lookup (`findOwnedTask`) and `recovery.residentHandle`, never through the call's capturing `task.get`, which by design refuses a parked row the current runtime does not own; it restores under the call's approval before anything attaches. A control verb's entry (`drive.ts` `enterControl`) restores the same way, so `cancel` of a reload-paused run reaches its child, and the unfolded-settle check reads through the owned lookup. A settled child counts as backed only when the new `recovery.owned` query (native task operation, non-capturing, answers exactly what the operation's capture would admit) says this runtime owns it, so a still-running run a hard kill stranded with a settled child goes through Native recovery instead of attaching that child. The DAG test fake now refuses every capturing read or action on a parked row like the Native operation. `claimDagRunLease` remembers the holder it displaced and its release writes it back instead of clearing it (P-05). Live-host QA defect D-2 fixed: `restoreAfterReload` arms Native's `continueInterruptedTurn` (prompt `HOST_RESPAWN_CONTINUATION`) for the child it restores; when Native reattaches it as a running task, the owned handle (`continueCutTurn`) delivers that prompt as a new turn of the new run epoch, observed under its own key, and drops the dead turn's `observation_uncertain`, so the call's `waitFor` folds the continued turn. The cut-off decision (`host/owned-child-outcome.ts` `retainedTurnCutOff`) reads only the retained records. Live-host QA defect D-3 fixed: the generation lease holder is now `2^52 + pid * 2^20 + generation`, so another process's holder is alive while its pid is (signal-0 probe, like Native's pid lease) and a second process's call is refused with `run_still_active` before any pause or recovery; a retired generation of the same pid stays dead. The runtime's DAG store (`fenceForeignTerminalRuns`) refuses any event for a run already terminal under another holder. Parity rows P-01, P-05, P-24, P-26 and P-27 updated.
