### Added

- OpenCode 2 gets the Native DAG `workflow` tool in blocking mode: `start` and `wait` with `detach=false` run the original Native engine and keep admitting the dependency frontier inside the call until the run settles; `snapshot`, `attach`, `guide` and `resume` answer as the original tool does. Every node starts as an attached owned child of that call's Native per-call operation, and no node starts after the call returns. Detached start or wait, `cancel`, `cancel_node`, `retry`, `send`, `amend`, nodes that name `load_skills` and nodes that resolve to process execution mode are refused with explicit messages. The tool is for root sessions only and can be turned off with the `omo-native-dag-enabled: false` plugin option.

## 2026-11-11 - OpenCode 2 blocking workflow tool (#14)

S6c of the OpenCode 2 DAG port. `v2/orchestration/native-dag/` builds the DAG store and manager under the root session's Native task state directory and runs one scheduler per blocking drive. Its `DagTaskPort` is a held port: while a call is bound it forwards to that call's operation (`startOwned`, `findOwnedTask`, `residencyChanged` through a new owned-start slice of the operation ports, and the existing task port for reads, waits and cancel); unbound, a node start is held and the scheduler retires without cancelling children. The next blocking call reattaches the children an earlier call admitted. Owned starts share the ordinary start's notification origin. The run lease is keyed by the plugin generation instead of the pid. References: https://github.com/hhgyu/oh-my-openagent/pull/14.
