### Fixed

- Local Codex installs on Windows no longer fail with ENOENT while materializing linked packages: each link is resolved from its real directory, so a relative workspace link reached through an npm junction points at the right package.
- Project-local Codex cleanup stops at the home directory and never treats `~/.codex` as project state, so an install with `CODEX_HOME` pointing elsewhere cannot rewrite the user's global Codex config.
- The ulw-loop state lock treats the Windows delete-pending `EPERM` on a lock another process is releasing as contention and retries within its deadline.
- The Codex plugin, LSP daemon and LSP tools MCP lockfiles record the current `lsp-core` dependencies, so `npm ci` no longer rewrites them.
