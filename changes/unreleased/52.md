### Fixed

- OpenCode 2 memory status now reports a memory file held out of sync because one change to it is larger than the sync batch limit: `sync.state` is `failing` (or `paused` while a refused entry also stands) and the failure names every held file, the ones shrinking will not fix, and the size limit, instead of an unexplained `unknown` failure or a bare pause.
- The OpenCode 2 memory sync host now tells a running OmO device service about the signed-in device, as OmO Native does: while the service reports no adopted device, sync re-sends the device from the credential it already holds, once per sign-in and with no extra credential store read, and a sign-in the service ends on refresh makes the device service forget the device.
