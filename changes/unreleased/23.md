### Added

- OpenCode 2 `workflow` nodes can name `load_skills` again. Each skill's content is prepended to the node's prompt exactly as the Native runtime does, at `start`, at `amend` for changed or added nodes, and at a `retry` with a new `prompt`. Your `skill` permission rules apply to the session that calls `workflow`: a denied skill fails that call and creates no run. A missing or disabled skill is reported as a run diagnostic and the node runs without it, as on Native.

## 2026-11-12 - OpenCode 2 workflow node skills (#23)

S6g of the OpenCode 2 DAG port. The S6g refusal is gone (the process-mode refusal stays). A `start`, `amend` or `retry` with `prompt` call first collects the skill names it can materialize (`native-dag/skills.ts`: every `load_skills` of the submitted definition, or the retried node's from the run record), then the component's per-call authority runs the S2 `authorizeSkills` for the genuine caller (the root session and its agent, under the caller and operation signals): a fresh `skill.list`, one `permission.assert({ action: "skill", resources: [id] })` per distinct SDK id, and a loader that serves only those names. Native's own `createDagSkillMaterializer` (now exported from `@oh-my-opencode/senpi-task/dag`) runs over that loader, so `effectivePrompt` (Native `buildSkillPrepend`), the `missing_skill` diagnostics and the pinned skill manifest are Native's. `start` and `amend` go through a manager built for the call (`NativeDagRuntime.managerFor`), and the call's scheduler options carry the materializer for the retry override's amend path. A verb that materializes nothing makes no host request and adds no turn. The runtime's base manager uses `callBoundSkillMaterializer`: a node with no skills keeps its prompt, and a node that would need skills outside such a call is refused. Parity row P-25 updated. Senpi bundles rebuilt for the new senpi-task export line. Real-host QA 46/46 on OpenCode 2.2.6. References: https://github.com/hhgyu/oh-my-openagent/pull/23.
