### Fixed

- On Windows, an aborted or timed-out memory git (for example a background repo maintenance pass stopped when a session closes) no longer leaves the real git and its pack-objects running in the memory repository after the call has returned. Removing or rewriting the repository right after such a stop no longer fails with EBUSY.

## 2026-11-27 - Stop the whole git process tree on a Windows abort (#127)

On Windows, `git` is the Git for Windows launcher, which runs the real git and that git's own children (pack-objects, hooks). An abort or timeout killed only the launcher, so `GitExec.run` settled while the rest of the tree kept writing in the repository for seconds. That surfaced as EBUSY when `maintenance.test.ts` removed its fixture after `dispose()`. The stop now runs `taskkill /T /F` on the launcher's tree, and the call settles once that has finished and the child's stdio has closed, within the existing exit drain. POSIX is unchanged: SIGTERM to git, then SIGKILL after the grace period on timeout.
