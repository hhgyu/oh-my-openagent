### Fixed

- On Windows, an aborted or timed-out memory git (for example a background repo maintenance pass stopped when a session closes) no longer leaves the real git and its pack-objects running in the memory repository after the call has returned. Removing or rewriting the repository right after such a stop no longer fails with EBUSY. If the process tree cannot be stopped within the existing kill grace, the call now fails with an explicit "process tree could not be stopped" error instead of reporting a clean cancel.

## 2026-11-27 - Stop the whole git process tree on a Windows abort (#127)

On Windows, `git` is the Git for Windows launcher, which runs the real git and that git's own children (pack-objects, hooks). An abort or timeout killed only the launcher, so `GitExec.run` settled while the rest of the tree kept writing in the repository for seconds. That surfaced as EBUSY when `maintenance.test.ts` removed its fixture after `dispose()`. The stop now runs `taskkill /T /F` on the launcher's tree, bounded by the existing kill-grace budget (`GIT_KILL_GRACE_MS`, 10 s). It counts as done only on taskkill exit code 0. A taskkill that cannot start, exits nonzero, or misses the deadline is killed together with the launcher, and the call rejects with `GitStopFailedError` (cause: `GitTreeStopError`). In that Windows runner every completion signal (exit, stdio close, the exit drain, the tree stop) goes through one settlement path, so the call and the git-activity lock it holds are released only after the tree stop has finished. An abort that arrives after git has exited is still reported as `GitAbortedError` and settles through the same close/drain path as any exit; an exited, reusable pid is never signalled. The runner (`exec-tree-stop-run.ts`, `stop-git-tree.ts`) is loaded only on Windows. On Linux and macOS `GitExec.run` runs the previous code unchanged: SIGTERM to git, then SIGKILL after the grace period on timeout.

The Senpi live QA drivers gained `memory-maintenance-abort-e2e.mjs`, which catches a real maintenance pass running under a live RPC session and proves it is stopped by the session's own shutdown with no git process left. `drive.mjs` now launches senpi through `bounded-senpi-run.mjs`, which owns the launch's whole process tree, so a run past its budget no longer leaves node and bun holding the sandbox on Windows. The QA tree stops refuse a pid of 0 or below, which `process.kill` would treat as a whole process group.
