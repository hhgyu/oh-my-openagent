### Fixed

- Senpi no longer leaves the session-start process sweep running after `session_shutdown`. Shutdown now stops the sweep's process enumeration (PowerShell on Windows, `ps` elsewhere) with its whole process tree and waits for it, for at most a fixed bound.
- A new thread gateway store opens faster. Schema migrations no longer flush to disk once per schema version, which took seconds on a busy Windows disk.

## 2026-11-25 - Stop the process sweep on shutdown and open new gateway stores faster (#116)

`session_shutdown` aborts the in-flight session-start sweep. The sweep's enumerations and `taskkill` calls run as owned process trees: an abort sends SIGTERM and then SIGKILL to the POSIX process group, or runs `taskkill /T /F` on Windows, and a descendant left holding the pipes after its parent exited is killed too. A reload or test cleanup therefore no longer finds a stray PowerShell recreating its temp directory, and shutdown can no longer hang on a wedged sweep. Gateway store migrations commit at `synchronous = NORMAL` in WAL mode and restore the previous level before any other write. Each step stays atomic, and a crash re-applies the newest steps from `user_version`.
