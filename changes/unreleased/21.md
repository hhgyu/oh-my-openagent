### Added

- OpenCode 2 `workflow` controls: `cancel`, `cancel_node`, `retry`, `send` and `amend` now work on OpenCode 2. Each control acts inside the `workflow` call that names it, through that call's own task receipts, and runs the original Native algorithm. `cancel` also stops the children of a background run that no call is driving. `retry` and `amend` re-enter the run in the same call: by default they start what can start now and return, and with `detach=false` they block until the run settles. `cancel_node` keeps the Native rule that it applies only to a run the user stopped, so it is refused until OpenCode 2 has a user stop. `load_skills` nodes and process execution mode stay refused, now for `amend` as well as `start`.

### Fixed

- OpenCode 2 `workflow action=send` no longer always fails with `Cross-parent operation send is not issued`. The send now goes through the call's own scoped send, and only to a node child of that run in this session; any other task is refused.
- OpenCode 2 `workflow action=amend` now re-runs a changed node with its amended prompt instead of the prompt it had before the amend.
- OpenCode 2 no longer wakes the root session twice for one node settle when a `workflow action=send` lands right after the wake. The send call now records children that already finished before it returns and names them in its result, and a run wake is identified by the settles it reports, so a wake that was already delivered is not posted again under a newer checkpoint.

### Changed

- The OpenCode 2 run wake id for a finished run now includes the run generation (sha256 of `dag:<runId>:terminal:<generation>`), so a run that finishes again after `retry` or `amend` gets a new wake instead of being deduplicated against the first one. Every run wake now ends with the Native DAG verification directive.

## 2026-11-12 - OpenCode 2 workflow controls (#21)

S6e of the OpenCode 2 DAG port. `v2/orchestration/native-dag/controls.ts` wires the tool's `cancel`, `cancelNode`, `retry`, `send` and `amend` seams to the Native `createDagRuntimeControls`, the scheduler's run cancellation and `createPausedNodeCancel`, with scheduler options bound to the current call's operation (the held DAG task port now delegates `sendToTask` to that call's send port). The engine's node send asks for all-scope authority, which the Native operation refuses; `native-dag/task-port.ts` drops `allScope` and `callerSessionId` and sends through the call's scoped send, after proving the task's DAG owner names this run (held port) and that the owned lookup of that owner key inside this root returns the same task (call port); anything else is refused with `node_not_found`. The V2 DAG manager now gets Native's no-skill materializer (`nativeDagNoSkillMaterializer`, effective prompt = submitted prompt), so `amend` no longer keeps a changed node's previous effective prompt. Every control runs under the runtime's per-run drive guard, so a run another call drives is refused with `run_still_active`, the wake owner stays quiet while the control runs and is re-armed after it. `driveDagRun` takes a control entry: a retry or amend re-entry is driven by the same call, detached by default or blocking with `detach=false`. Cancel of a held run re-attaches the children earlier calls admitted, so the Native cancellation cancels them through the call. The terminal wake id moved from `dag:<runId>:terminal` to `dag:<runId>:terminal:<generation>`. A control with no re-entry (`send`) now folds children that settled before it inside the call (`driveDagRun` runs a detached fold when the run is running and a settle is unfolded), and the frontier wake id moved from `dag:<runId>:<checkpointSeq>` to `dag:<runId>:frontier:<settles>` (canonical node, task, run epoch and status of each reported settle); the wake owner reuses a journal row of the run that carries the same id (`findInput`), so an ACKed settle is not re-announced after a steer moves the checkpoint (QA defect D-3). Parity rows P-24 and P-26 updated. References: https://github.com/hhgyu/oh-my-openagent/pull/21.
