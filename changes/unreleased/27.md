### Added

- In OpenCode 2, an `eval` cell can start a Native task with `tools.task(...)` and hand the child tools defined in its kernel: define `tool(function double({ n }) { return n * 2 })` in a JavaScript cell, then `await tools.task({ prompt: "...", tools: ["double"] })`. The child calls them through one `omo_kernel_tool` tool (`{ name, args }`), which it sees only while the grant is live and which lists exactly the tools it was given. The same rules as Native apply: read-only agents, process children, unknown or colliding names are refused, and a `task` call made outside an `eval` cell cannot grant kernel tools. After a kernel reset the child's calls fail with `kernel_tool_stale`; after the parent's eval session is deleted or eval stops, they fail with `tools_unavailable`. A user deny rule on `omo_kernel_tool` removes the tool from every child.

## 2026-11-12 - OpenCode 2 kernel tool bindings for Native task children (#27)

S9d of the OpenCode 2 CodeMode port. A cell's `tools.task` reaches the plugin-owned `task` host tool (`v2/tools/eval-task-host-tool.ts`) with the cell's capability proxy; the worker now stamps every host-tool call with the eval call whose cell is running (`codemode-worker-runtime.ts`), and `native-eval.ts` resolves it to that call's own SDK context (`bindEvalCallers`), so a detached or finished cell cannot spawn. A late-bound port (`createEvalTaskPort`, wired in `v2/index.ts`) hands the call to the Native task component, which runs the SAME public `task` operation (`createNativeTaskBridge().invokeTask`, same argument normalization, permission prompts and admission) under the eval call's identity, and lends the capability to exactly that call through a ledger keyed by session and call id (`native-task/kernel-binding.ts`). The component's task context passes it to senpi-task as `ctx.kernelTools`, so the unchanged Native `resolveTaskKernelTools` / `resolveKernelToolGrant` decides the grant. The approved spec's grant is bound by the child guard binding: a new Effect-scoped `omo_kernel_tool` registration (acquired before the owned-child guard, so the guard wraps it, excluded from the child catalog) claims `kernel-live-bindings` with one target per descriptor slot and one producer per owned child (custody by session and agent, revoke and join like the other live producers); a `context` hook hides it from unbound sessions and describes the bound child's own grant. `owned-runner.ts` now refuses a kernel grant only when that binding is missing; the unguarded path still refuses. Each child call goes through `v2/tools/kernel-tool-proxy.ts`: the descriptor's fenced generation and revision, the Native `{ kernel_tool, value | error }` envelope, codemode's error codes preserved across the worker (`kernel_tool_stale` after a reset), the child session as `invoker`, and when the capability advertises `invokeScope` the grant's scope with the plugin-owned eval host tools (`task`) always denied, because the worker would run such a nested call as the parent's eval call. `codemode-capability.ts` proxies now end with their eval session: on session release, worker loss or eval dispose every call, including one in flight, fails `kernel_capability_released`, which the child sees as `tools_unavailable`. Real-host QA 49/49 x3 on OpenCode 2.2.6. References: https://github.com/hhgyu/oh-my-openagent/pull/27.
