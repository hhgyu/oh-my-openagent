### Fixed

- `bun run build` (and `bun install` through `prepare`) no longer fails on Windows while a running OpenCode or Senpi has the checkout loaded. `build:shared-skills-assets` mirrors `dist/skills` in place instead of `rm -rf && cp -R`, and the Senpi extension build stages every pass in a temp directory and renames the finished files into place, skipping identical bytes. A file Windows keeps locked past a bounded retry fails the build with an error naming the holding process instead of leaving stale or half-deleted output.
- `packages/omo-native/bin/lib/service-auth.generated.js` is regenerated from its current sources, and the CI build job now checks it before rebuilding, so a stale committed bundle fails CI.

## 2026-11-15 - Windows build survives held outputs; service-auth bundle freshness gate (#69)

`script/windows-safe-replace.mjs` writes build outputs through a sibling temp file and rename. It retries only Windows sharing violations (EBUSY/EPERM/EACCES/ENOTEMPTY, and UNKNOWN for a Bun memory-mapped file) for about 4.5 s, then throws `LockedOutputError` with the holder from the Restart Manager. `script/sync-directory.mjs` uses it for `dist/skills`, and `build-extension-core.mjs` uses it for every Senpi bundle; the emitted Senpi bytes are unchanged. The service-auth bundle had been stale since the thread-core gateway move, and no test leg saw it, because `prepare` rebuilt the file before `build-service-auth.test.ts` compared it. The ubuntu build job now runs `bun script/build-service-auth.ts --check` after an `--ignore-scripts` install. References: https://github.com/hhgyu/oh-my-openagent/pull/69.
