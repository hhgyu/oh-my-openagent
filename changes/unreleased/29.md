### Added

- OpenCode 2 memory sync: if you are signed in with `omo login` and `memory.sync.enabled` is on (the default), each bound memory now syncs end-to-end encrypted across your devices, as it does on Native. On a new device, sync starts after the first memory write, without a restart. The sync engine loads only when it is needed, and it stops when the plugin unloads.
- OpenCode 2 memory sync RPC: `omo.memory.sync` serves Native's five methods (`enable`, `pending`, `approve`, `status`, `devices`) for device pairing and the device list. The new `omo.memory` RPC answers `status` for a session and sends an `updated` event after a sync converge, a sync failure change or a journal settle.

## 2026-11-12 - OpenCode 2 memory sync, sync RPC and memory status (#29)

S8b to S8d of the OpenCode 2 memory port, over the host-neutral runner that S8a moved into memory-core. `v2/memory/sync/runtime.ts` holds one acquire per distinct bound repo and releases all of them in cleanup, before the binder clears. A repo whose git config does not exist yet (a fresh device binds before its first write seeds the repo, and the runner's space resolution writes that config) waits, and is acquired on the next bind or `experimental.idle` settle after the write. Without that, real-host QA showed the runner's failed start blocked sync until a restart. A failed acquisition releases its runner hold and gives up its slot, so the next edge retries; there is no timer. Senpi has the same fresh-device gap until its session ends, because it acquires at bind and the shared runner keeps a failed start held; fixing that is a memory-core runner change for both hosts. It is gated by `memory.sync.enabled` with the `agents.<id>.sync` override; there is no schema change, the unified config already has the key. It imports only types. The sync host (`sync/host.ts`: memory-core runner, device-session resolver, `registerSyncRpc` coordinator) loads through `import()` on the first enabled bind or the first sync call. The Loro engine (`sync/engine-runtime.ts`) loads one more `import()` later, so a temp-dir bundle of `v2/index.ts` keeps Loro and the runner out of the static graph of the memory chunk. The CLI account source moves, unchanged, from omo-senpi `device-session/{account-source,cli-account-operation}.ts` to `packages/omo-opencode/src/cli/service-auth/sync-account/` behind the new package export `@oh-my-opencode/omo-opencode/service-auth/sync-account`. The location follows the dependency direction: the source needs service-auth and memory-core, memory-core must stay harness-neutral, and Senpi already depends on omo-opencode service-auth. Its tests (`cli-operation.test.ts`, `account-source-freshness.test.ts` with `sibling-writer.fixture.ts`) move with it. Senpi imports the shared source from its lazy device-account sidecar and takes the account types from memory-core; the desktop channel, `selected-account-source` and `account-runtime-loader` stay in Senpi. The V2 sync host imports the same module. The ceremony claims (`sync/claims.ts`) use Senpi's files and team-core lock, so a V2 host and a Senpi host on one memory root exclude each other. `sync/rpc.ts` registers `omo.memory.sync` with the five methods. Its inputs are validated by the memory-core coordinator, so bad requests get Senpi's refusal shapes. It has one owner per registration whose signal is the component lifetime. Like Senpi's, it is served whatever `memory.sync.enabled` says. The dotted id follows a read of the 2.2.6 binary (`Rpc.register` keys by the raw id; calls route through `/api/rpc/:rpcID/:method`). `status-rpc.ts` and `status-snapshot.ts` serve `omo.memory` `status({ sessionID })` and `rpc.omo.memory.updated`: per session, deduplicated by content, after a HEAD move (`sync/head-watch.ts`, which also sees converge commits), a shown-failure change or a journal settle. The snapshot has the journal, reflection and sync fields, from lock-free reads; it has no `repo` block. `packages/omo-opencode/tsconfig.json` gains `allowImportingTsExtensions`, as omo-senpi did, because the memory-core sync sources use `.ts` import paths. The root `tsconfig.json`, which only emits declarations, gains `allowImportingTsExtensions` and `emitDeclarationOnly`. The declaration emit stays inside `packages/omo-opencode/src`, because memory-core resolves as a package and gets no `.d.ts` files. Senpi bundles rebuilt. Parity row P-22 updated. Tier A real-host QA on OpenCode 2.2.6 passed 44 of 45 checks; the one failure was environmental. The dotted ids were accepted live, a commit converged from one sandbox to the other, `rpc.omo.memory.updated` arrived about 4.5 s after the write, and the loopback keyring entries were deleted with zero leftovers. Pairing (tier B) was only smoke-tested. References: https://github.com/hhgyu/oh-my-openagent/pull/29.
