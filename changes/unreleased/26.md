### Fixed

- OpenCode 2: unloading the plugin from a project (for example a location evict) no longer fails with HTTP 500 after you removed a lead session whose Native tasks had run. OpenCode removes a removed session's children with it, and the plugin used to keep trying to park those already-removed children, so its cleanup failed. It now closes them, logs a warning naming the task, and still parks every live child so the next load restores it.

## 2026-11-12 - OpenCode 2 Native close retires host-removed children (#26)

Real-host QA of S9c (`.omo/evidence/20261112-s9c-native-eval/actual-qa/`, residual R2) found that `DELETE /api/debug/location` answered HTTP 500 on a host where lead LA ran Native tasks and was then removed with `session.remove`. OpenCode 2.2.6 removes the lead's children with it, but the Native runtime of LA stayed open. On plugin close, `retireChildren(parent, "dispose")` parked each resident child through `suspendOnSessionShutdown`, then `OwnedSessionLifecyclePort.suspend` ran `control.detach()`, then `backend.interrupt(child)`. That call's `host.session.get` failed with the host's `Session.NotFoundError`, which became `SessionBackendError("uncertain", "Child interruption acknowledgement uncertain; ...")`. Both of LA's children failed this way (`Owned descendant suspension incomplete`), so the runtime, the task service and the component close all failed. Their guard stages were never parked or released, so the owned child tool guard's scope finalizer threw `Child closure custody incomplete; deny hooks retained` (`v2/host/owned-child-tool-guard.ts`), and that is the error the host answered 500 with. The fix adds `v2/host/session-absence.ts` (`isHostSessionAbsent`: the host's own `Session.NotFoundError` or the protocol `SessionNotFoundError`, naming this exact session ID). Session-backend `cleanup` now records the genuine `closed` receipt when the host says the child no longer exists. A new read-only probe, `backend.hostRemoved(child)`, backs `owned-lifecycle.ts` `suspend`: when a park fails and the probe proves the child is gone, it ENDs the control instead, which closes the journal row, releases the guard stage against that closed receipt and records no `suspended` receipt, so `restoreAfterReload` does not try to revive it. The runtime logs this with the task ID, the child session ID and the park failure. A failure that does not prove absence (transport, location, a different session ID, or a failing probe) still fails the close exactly as before, so the S6f park-and-restore guarantees for live children are unchanged. The owner regression is in `restart-continuation.test.ts`: two finished children, the host removes one, then a reload. Before the fix it reproduced the exact guard error; now close and the guard finalizer complete, the removed child is not removed again or restored, and the live child parks and restores. `session-backend.test.ts` checks that a not-found error naming another session stays uncertain. Real-host QA: evict 204 with one warning per removed child (pre-fix build 500). References: https://github.com/hhgyu/oh-my-openagent/pull/26.
