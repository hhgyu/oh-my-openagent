# Changelog

<!-- changelog-baseline: v2 -->

All notable changes to this fork, [hhgyu/oh-my-openagent](https://github.com/hhgyu/oh-my-openagent) (OmO for OpenCode 2), are documented in this file.

The fork's OpenCode 2 host work began on 2026-10-21 and lands on the `v2/dev` branch. Its last upstream merge is [code-yeongyu/oh-my-openagent@b036a83c62](https://github.com/code-yeongyu/oh-my-openagent/commit/b036a83c62) (2026-11-20, upstream v5.1.79). Upstream's own history and later releases are in the [upstream changelog](https://github.com/code-yeongyu/oh-my-openagent/blob/dev/CHANGELOG.md); this file lists only the fork's changes. See [D-048](docs/DECISIONS_V2.md).

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

## [v2-baseline] - 2026-11-25

**The Senpi entry bundle no longer carries a second copy of the builtin agent prompts.** `omo.js` drops from 1,475,912 to 1,436,572 bytes, leaving 39,428 bytes of headroom under its 1,476,000 byte budget. Behavior is unchanged: the task sidecar still loads the agents. ([#92](https://github.com/hhgyu/oh-my-openagent/pull/92))

### Fixed

- Thread model switches honor thinking suffixes on OpenCode v2 and Senpi and identify an unavailable provider. A refused suffix restores the previous model and thinking level, and reports a partial change if the initial switch or restoration cannot be confirmed. ([#108](https://github.com/hhgyu/oh-my-openagent/pull/108))
- Closing the thread gateway now waits for requests already in progress and for the database worker to exit, even if two callers request shutdown at once. ([#106](https://github.com/hhgyu/oh-my-openagent/pull/106))
- An offline thread can receive another message after queued deliveries expire. Messages already in the target's intake remain available for that target to reconcile. ([#105](https://github.com/hhgyu/oh-my-openagent/pull/105))
- Memory journals reuse unchanged transcript rows and reload the file after an external rewrite or replacement, so deleted rows do not reappear in reflection snapshots. ([#104](https://github.com/hhgyu/oh-my-openagent/pull/104))
- A newer Senpi settle for the same session supersedes redundant observer work without cancelling an admitted durable write. ([#104](https://github.com/hhgyu/oh-my-openagent/pull/104))
- OpenCode 2 thread tools use Code Mode call examples, offer `/sessions` when links cannot be opened, and describe what interruption actually stops. ([#102](https://github.com/hhgyu/oh-my-openagent/pull/102))
- OpenCode QA resolves relative database overrides against the OpenCode data directory and handles Windows CRLF output when locating the active database. ([#101](https://github.com/hhgyu/oh-my-openagent/pull/101))
- OpenCode 2.3 and later pause Kibitzer automatic recall to prevent repeated `Kibitzer finished` messages and unsolicited parent turns. OpenCode 2.2 retains Kibitzer, and normal subagent completion reports remain available. ([#96](https://github.com/hhgyu/oh-my-openagent/pull/96))
- The `opencode-qa` skill's session lookup scripts (`db-session-by-id.sh`, `db-session-by-name.sh`, `db-session-by-text.sh`) and `export-roundtrip.sh` work on OpenCode 2.x. They returned nothing there because 2.x has no `opencode db` subcommand and stores sessions in `session_v2` and messages in `session_message`; they now read that layout read-only through `scripts/lib/db-query.mjs` and use `opencode session export`. The 1.x path is unchanged. ([#95](https://github.com/hhgyu/oh-my-openagent/pull/95))
- On OpenCode 2, when two server processes serve one project (a `serve --service` restart replaces the previous service), only one of them now revives a task child an OpenCode restart left behind. The other no longer posts a `not revived: Owned unadmitted cleanup incomplete` notice, no longer refuses that child's tool calls with `Owned child is not executable`, and takes the child over once the first process lets it go. A parent call that reaches a child the other process still holds says so instead of `Operation task has no original owned membership`. ([#94](https://github.com/hhgyu/oh-my-openagent/pull/94))
- `task_cancel` ends a task child that a restart left parked or stranded, or whose revival failed, instead of failing with `no original owned membership`; it no longer revives the child it is cancelling first, and a cancelled child does not revive at the next start. ([#94](https://github.com/hhgyu/oh-my-openagent/pull/94))
- A plugin location reload while a revived task child's turn runs hands the child to the reloaded plugin: the reload no longer waits forever for that turn, and task calls are no longer refused for 30 s with `previous plugin generation ... still parking`. ([#94](https://github.com/hhgyu/oh-my-openagent/pull/94))
- An OpenCode 2 task child that a server restart cut off while a tool was running now finishes its revived turn with one completion notice, and the parent's next `task_send` continues it. Before, the host's settlement of the interrupted tool call made the revived turn's observation uncertain (`unmatched-step`): the task stayed `running`, no completion arrived and `task_send` was refused. ([#93](https://github.com/hhgyu/oh-my-openagent/pull/93))
- When the restarted OpenCode host itself resumes such a child and the revival adopts the answer it finished, the parent's next `task_send` continues the child instead of failing with `could not be revived: Owned prior turn is not positively settled`. ([#93](https://github.com/hhgyu/oh-my-openagent/pull/93))
- Memory locks on macOS: a lock waiter reads the start time of an owner that has exited but has not been reaped in-process. Before, it spawned `/bin/ps` for that owner. When Bun lost that child's exit notification, the waiter stayed parked on the probe past its wait deadline (the `operation-boundary-lock` CI hang). ([#91](https://github.com/hhgyu/oh-my-openagent/pull/91))
- Senpi: a background task child that was mid-turn when its parent session quit continues its work when the session is resumed. With senpi 2026.11.12 it instead ended with the error "restored session has no assistant output". ([#90](https://github.com/hhgyu/oh-my-openagent/pull/90))
- Senpi QA: the quit-resume lanes of `task-e2e` and `task-id-race-qa` pass on senpi 2026.11.12 and on Windows. ([#90](https://github.com/hhgyu/oh-my-openagent/pull/90))
- On Windows, archive listing and extraction (the comment-checker download, zip binaries) use the bundled `System32\tar.exe`, so they work when Git for Windows' GNU tar comes first on PATH. Before, that tar read `C:\...` as a remote host, the download failed, and the comment-checker never installed. ([#86](https://github.com/hhgyu/oh-my-openagent/pull/86))
- Session-history project discovery compares directories by their exact NTFS file IDs. File IDs above 2^53 used to drop to a case-folded path comparison, so whether two distinct directories merged depended on their IDs. ([#86](https://github.com/hhgyu/oh-my-openagent/pull/86))
- Memory component cleanup waits for the transcript journal writes that the final facts drain started, so none land after cleanup has returned. An aborted journal reconcile stops waiting on a stalled host read, which keeps shutdown bounded. ([#86](https://github.com/hhgyu/oh-my-openagent/pull/86))
- Senpi: a background-task completion, team message or continuation no longer starts a new turn on a session whose shutdown already began; `senpi -p` with a background child now exits instead of staying alive for minutes. Refused wakes are redelivered by the next session. ([#85](https://github.com/hhgyu/oh-my-openagent/pull/85))
- Senpi: a background-task completion that arrives right after the parent's run settled is delivered at once instead of after the 200 ms batch window. ([#85](https://github.com/hhgyu/oh-my-openagent/pull/85))
- Windows: every remaining Senpi QA driver launches senpi attached and hidden and kills its process tree with `taskkill /T /F`, so none of them opens a console window. ([#85](https://github.com/hhgyu/oh-my-openagent/pull/85))
- opencode-qa helpers can no longer leave orphaned `opencode serve` processes behind. Servers and fake providers now start through `scripts/lib/serve-guard.mjs` (a Windows kill-on-close Job Object, or a POSIX process group, plus a watch on the driver pid), so they stop with the driver even when the driver is SIGKILLed or `taskkill /F`ed. Each helper's self-test now proves that no server survives a forced driver kill. ([#84](https://github.com/hhgyu/oh-my-openagent/pull/84))
- Windows: the memory engine's space sync no longer opens a console window for each `git` call. ([#83](https://github.com/hhgyu/oh-my-openagent/pull/83))
- Windows: the Senpi task and team QA drivers no longer open a visible console window for every senpi run they launch. ([#83](https://github.com/hhgyu/oh-my-openagent/pull/83))
- A senpi-task in-process child torn down while its prompt still waits in engine preflight now cancels that prompt instead of letting the turn start on the disposed session. ([#83](https://github.com/hhgyu/oh-my-openagent/pull/83))
- Keep V2 task children that an OpenCode host upgrade ended readable through `task_output` by id and by name, and list them in its "Known tasks" hint. ([#82](https://github.com/hhgyu/oh-my-openagent/pull/82))
- Notify the parent exactly once for every child an upgrade fenced, including a batch member that had already ended without its end being reported. ([#82](https://github.com/hhgyu/oh-my-openagent/pull/82))
- A V2 task child whose final record write failed once now settles after a retry instead of staying `running`, and a child that finished entirely between two observers settles from the host transcript with one parent notice. ([#81](https://github.com/hhgyu/oh-my-openagent/pull/81))
- A child that finished by itself across a `location/reload` settles without the restart continuation. ([#81](https://github.com/hhgyu/oh-my-openagent/pull/81))

- Load the OpenCode V2 plugin on stable host versions >=2.2.6, including 2.3.0, while preserving joined-cancellation and backend capability checks. ([#77](https://github.com/hhgyu/oh-my-openagent/pull/77))

([#76](https://github.com/hhgyu/oh-my-openagent/pull/76))
- An OpenCode 2 task child whose last run had already finished when a plugin reload or a server restart took its observer no longer stays `running` forever with no completion: the restored run settles once with the answer the earlier observer recorded, after the host reports the session idle, and the child gets no restart continuation. - OpenCode 2: an in-process location reload or evict while a Native task child or `workflow` node was still mid-turn no longer strands it. The previous generation now parks its children as soon as OpenCode shuts the location down. The next generation's first call waits for that park, then restores the child and continues its cut-off turn exactly once, as after a server restart. A `task_send` to such a child revives it the same way before its message is delivered. OpenCode removes a removed session's children with it, and the plugin used to keep trying to park those already-removed children, so its cleanup failed.
